# Handoff: FIFA 17 online match died at kickoff — desync from Wine's built-in C runtime, FIXED

State on 2026-09-08 ~15:45 Europe/Istanbul. Nothing committed. Bottle left in a known-good state (see "State at handoff"). Supersedes the network-first plan in `ONLINE-KICKOFF-ANALYSIS.md`.

## Resume in one paragraph

**Fixed and verified on 2026-09-08 ~16:15 Europe/Istanbul.** FIFA 17 PvP matches on the Mac died at kickoff because FIFA's lockstep simulation desynced from the opponent (the game's own match report carried `GDESYNCEND`; transport was clean). The Mac-only difference was Wine loading its **built-in** `msvcr120`/`msvcp120` (VS2013 C runtime) instead of the Microsoft copies in the game folder, so transcendental maths differed in the last bit. With `"msvcr120"="native,builtin"` and `"msvcp120"="native,builtin"` under `[Software\\Wine\\DllOverrides]` in the Aurora17 bottle, run `20260908T131046Z-fifa17-baseline` played 99 real seconds (game clock 336 s, a goal scored, `PKTLOSS 0`, `FPSAVG 30`) against a live opponent and only ended when the user alt-tabbed out (that ends with `GDESYNCEND 2` too — focus loss stalls the sim). Three earlier baseline runs desynced within 0–8 s of kickoff. The "all-seven native override kills startup at ~25 s" result from earlier today was **wrong**: both runs that died before the menu had a stale Wine session (`services.exe`/`explorer.exe` from the previous launch) alive underneath — commit 8b092a3's loader-lock case — and one of them did not even have the override active. The fix is being folded into `setup.sh` (`--check`, `--report`, install), `tests/`, and the docs (Opus agent, in flight at the time of writing; verify with `git diff` before trusting).

Blaze frame layout used by the decoder: `u32 size | u16 0 | u16 component | u16 command | u16 error | u16 msgtype/id | u16 0`, payload heat2 TDF (type 7 = variable TDF). Component 0x0004 GameManager, 0x001c GameReporting, 0x0009 Util, 0x7802 UserSessions, 0x000a is the 15 Hz keepalive chatter.
